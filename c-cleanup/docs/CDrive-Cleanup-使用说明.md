# CDrive-Cleanup 使用说明

## 1. 功能和安全边界

`CDrive-Cleanup.ps1` 是 Windows 10 C 盘的保守清理和空间分析脚本。

旧版入口 `Clean-CDrive.ps1` 已移除，避免项目中保留重复入口；请统一使用 `CDrive-Cleanup.ps1`。

默认运行只读扫描，不删除任何文件。只有明确使用 `-Execute`，并在程序提示时准确输入 `CLEAN`，才会执行清理。

脚本自动处理的范围非常有限：

- 当前用户临时目录中的过期文件；
- `C:\Windows\Temp` 中的过期文件；
- 当前用户和系统 Windows 错误报告目录中的旧报告。

默认保留期限为：临时文件 7 天，错误报告 30 天。

脚本不会：

- 关闭休眠或修改虚拟内存；
- 修改注册表、服务、电源策略或系统权限；
- 结束进程、重启服务或下载软件；
- 清空回收站；
- 删除微信、企业微信、QQ、下载、桌面、文档、项目、模型和开发工具数据；
- 清理 `Windows Installer`、`WinSxS`、驱动、Windows Update 或安装程序。

任何文件删除都不是数学意义上的“零风险”。本脚本的安全承诺是：不主动修改系统配置、不处理个人数据、不接受任意删除路径，并且删除前后再次校验白名单和文件属性。

## 2. 运行要求

- Windows 10 专业版；
- Windows PowerShell 5.1；
- 建议以管理员身份打开 PowerShell，以便完整读取系统目录；
- 不需要网络连接；
- 不需要安装第三方程序。

管理员权限不是执行删除的必要条件。没有管理员权限时，脚本会跳过无权访问的目录并记录原因，不会强制提权。

## 3. 打开 PowerShell

1. 打开“开始”菜单。
2. 搜索“Windows PowerShell”。
3. 需要读取更多系统目录时，右键选择“以管理员身份运行”。
4. 进入脚本目录：

```powershell
Set-Location -LiteralPath 'D:\electron\c-cleanup'
```

如果脚本来自浏览器下载并被 Windows 标记为阻止，可以只解除这个脚本文件的阻止标记：

```powershell
Unblock-File -LiteralPath '.\CDrive-Cleanup.ps1'
```

不要为了运行脚本而修改整个系统的执行策略。

## 4. 首次使用：只读扫描

推荐首次执行以下命令：

```powershell
.\CDrive-Cleanup.ps1
```

这个命令只扫描，不删除。默认使用“快速模式”，重点读取临时目录、用户数据目录和常见开发缓存，通常比全盘枚举更快。

如果需要枚举整个 C 盘的大文件和顶层目录，再使用深度扫描：

```powershell
.\CDrive-Cleanup.ps1 -DeepScan -MaxScanSeconds 300
```

深度扫描是只读操作，可能需要几分钟。扫描不完整时，即使加了 `-Execute`，脚本也会自动禁止删除。

扫描完成后会显示：

- C 盘清理前剩余空间；
- 安全白名单中的过期临时文件；
- 单文件不小于 512 MB 的大文件；
- 只允许人工判断的系统文件、程序数据和用户数据；
- 访问被拒绝、文件被跳过和重解析点信息。

## 5. 查看报告

报告目录：

```text
D:\electron\c-cleanup\reports\
```

每次运行会生成：

- `CDrive-Report-yyyyMMdd-HHmmss.json`：完整结构化报告；
- `CDrive-Report-yyyyMMdd-HHmmss.csv`：便于筛选和排序的候选列表。

日志目录：

```text
D:\electron\c-cleanup\logs\
```

日志会记录扫描、跳过、模拟删除、实际删除和错误信息。脚本不会把新日志写到项目根目录。

## 6. 模拟执行

如果想查看执行模式将处理哪些文件，但不进行删除：

```powershell
.\CDrive-Cleanup.ps1 -Execute -WhatIf
```

模拟模式会逐文件输出“模拟删除”，但不会调用实际删除操作。

## 7. 执行安全清理

确认已经查看扫描报告，并且不需要保留临时目录中的旧文件后，执行：

```powershell
.\CDrive-Cleanup.ps1 -Execute
```

脚本会再次提示确认。只有准确输入下面的内容才会继续：

```text
CLEAN
```

输入其他内容、关闭窗口或出现错误都会取消或跳过清理。

清理过程中：

- 逐文件处理，不删除目录本身；
- 被占用文件自动跳过；
- 系统、只读和重解析点文件自动跳过；
- 删除失败不会影响其他文件；
- 每个结果都会写入日志和 JSON 报告。

脚本不会因为空间仍然不足而自动扩大删除范围。

## 8. 参数说明

```powershell
# 默认只读扫描
.\CDrive-Cleanup.ps1

# 默认只读扫描；该参数主要用于明确表示不执行删除
.\CDrive-Cleanup.ps1 -WhatIf

# 模拟执行
.\CDrive-Cleanup.ps1 -Execute -WhatIf

# 执行安全清理，临时文件默认保留 7 天
.\CDrive-Cleanup.ps1 -Execute

# 仅在明确了解影响后，调整临时文件保留期限
.\CDrive-Cleanup.ps1 -Execute -TempMinAgeDays 14

# 调整错误报告保留期限
.\CDrive-Cleanup.ps1 -Execute -ReportMinAgeDays 60

# 延长只读诊断时间；扫描不完整时仍不会执行删除
.\CDrive-Cleanup.ps1 -MaxScanSeconds 300

# 深度扫描整个 C 盘，仅用于分析，不会自动删除
.\CDrive-Cleanup.ps1 -DeepScan -MaxScanSeconds 300
```

`-MaxScanSeconds` 默认是 90 秒，允许范围为 10 到 3600 秒。达到扫描上限时会生成“部分扫描”报告，并且即使指定了 `-Execute` 也会自动禁止删除。`-DeepScan` 只改变扫描范围，不扩大自动删除白名单。脚本不提供自定义路径参数，也不提供强制删除参数。

## 9. 报告中的人工复核项目

报告中的以下内容不会自动删除：

- `hiberfil.sys`、`pagefile.sys`、`swapfile.sys`；
- `C:\Windows\SoftwareDistribution`；
- `C:\Windows\Installer`；
- `C:\Windows\WinSxS`；
- `C:\Windows\Prefetch`；
- `C:\Windows.old`；
- 回收站；
- `Program Files` 和 `Program Files (x86)` 中的软件；
- npm、pnpm、Codex 等开发缓存；
- 微信、企业微信、模型和其他个人应用数据；
- 下载、桌面和文档目录。

这些项目需要使用软件自己的设置、Windows 设置中的存储管理或“应用和功能”卸载，不要直接删除系统目录。

尤其不要手动删除 `WinSxS`、`Windows Installer`、驱动目录或虚拟内存文件。

## 10. 清理后验证

清理完成后：

1. 查看日志中的“清理后 C 盘剩余”。
2. 确认实际空间变化没有出现负数或异常。
3. 重新打开文件资源管理器、浏览器和常用开发工具。
4. 保存一个普通文件并重新打开。
5. 如果系统有待重启更新，按正常流程重启一次。

如果清理后空间几乎没有变化，说明主要占用来自系统文件、安装程序、个人数据或开发工具数据，脚本不会继续强制删除。

## 11. 被占用、权限不足和报告异常

- “被占用”：文件正在被程序使用，脚本会跳过，关闭相关程序后可在下次扫描确认。
- “权限不足”：以管理员身份重新扫描；脚本不会接管权限或修改 ACL。
- “重解析点/符号链接”：脚本主动跳过，防止目录跳转越界。
- 扫描时间较长：C 盘完整空间分析需要枚举文件，期间不执行删除。
- 报告生成失败：先确认脚本目录可写，并检查 `logs` 目录中的错误信息。

## 12. 回滚和备份说明

本脚本没有通用回滚功能，因为安全清理使用的是直接删除，而不是移动到回收站。自动清理范围只包含过期临时文件和错误报告，不包含个人文件和系统配置。

如果临时文件中有正在排查问题所需的日志，请在执行前复制到其他磁盘。若误删了重要文件，应立即停止继续操作，并使用已有备份或专业恢复工具；恢复成功不能保证。

## 13. 维护建议

- 第一次只运行扫描，查看报告后再决定是否执行。
- 不要把 `-Execute` 放入计划任务或开机启动。
- 定期查看大文件报告，优先通过应用自身设置迁移数据。
- Windows 自带 Storage Sense 可以作为人工维护工具，但不要为了省空间关闭系统保护功能。

## 14. Windows 官方工具的人工兜底

如果报告显示主要空间在 Windows 更新、旧系统版本或组件存储，优先使用 Windows 自带界面：

- 设置 → 系统 → 存储 → 存储感知/临时文件；
- 搜索“磁盘清理”，选择“清理系统文件”；
- WinSxS 需要使用系统维护任务或 DISM 分析后再决定，不能直接删除目录。

脚本不会自动运行 DISM、磁盘清理或 Storage Sense，因为这些操作涉及系统维护决策，需要用户在 Windows 界面中确认。
